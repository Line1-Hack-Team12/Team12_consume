## 2026-11-09 · 4장 28행 · 예비 결과

**이 숫자는 예비 결과다.** 28행으로는 "금액 오독률 2% 이하"를 통계적으로 주장할 수 없다 (0/28의 95% 상한은 약 10%). 또 정답 템플릿을 추출 결과에서 만들어 검수자가 고치는 방식이라 검수자가 놓친 모델 오류는 정답이 된다. 수용 기준 충족 주장은 아래 "세트 확대" 뒤로 미룬다.

| 2 | 카카오뱅크 통장 | 날짜 헤더 + 최신순, 맨 위 행은 헤더 잘림 | 7 |

Haiku 의 방향 1건은 부호 없이 "50,000원 … → 내 우리계좌" 로 표시된 토스 입금 행. 오독이 아니라 unknown 으로 검토 큐에 넘긴 것이지만, Sonnet·Opus 는 화살표 방향으로 입금을 읽어냈다.
Haiku 1차 실행에서 시각을 "09:07:55" 로 적어 시각 일치가 85.7% 였고, 이를 계기로 코드에서 HH:MM 정규화를 넣었다 (f03-0.5).

**잠정 결정.** Sonnet 5.5 유지. 이 세트에서 Opus 와 정확도 차이 없음. 지연 시간은 1회 실행이라 비교 근거로 쓰지 않는다.

f03-0.6 으로 같은 4장 재실행: 0/28 유지, 행 id 28개 유일, raw_text 에 잔액 포함 0건, 플래그 분포 low_confidence 2 · date_missing 2 · merchant_missing 1 · month_mismatch 1.

## 독립 리뷰 (2026-11-09, 등급 B) 반영 → f03-0.6

리뷰어가 확인한 결함과 조치:

| 결함 | 조치 |
|---|---|
| 불가능·비정형 날짜("2026-10", "02-30")를 슬롯 1일 거래로 생성 | `resolve_date` 가 `""` 반환 → `date_missing`. 연도 경계 12월→1월도 처리 |
| 한 장의 예상 밖 예외가 job 전체를 날림 | `guarded` 에 catch-all → 그 장만 `failed/INTERNAL`, 메시지는 예외 타입명만 |
| 전부 skipped 인 job 이 `failed` + 재시도 대상 없음 | 새 상태 `no_transactions` (캡처 교체 안내) |
| partial 재시도 병합 미구현, 행 id 랜덤 | `merge_retry()` + 결정적 id `sha1(asset:row|slot)`. 거래 수 불변 테스트 |

| 이름·계좌번호 미추출이 프롬프트 의존 | `scrub_sensitive()` 가 계좌·카드번호·"잔액 n원" 제거 (코드 가드) |

단위 테스트 26 → 30개. 같은 4장 재실행 0/28 유지, 스크럽 라벨 출력 0건(정상 텍스트 훼손 없음).

알고 있는 설계 제약: 행 id 가 (자산, 행 순서, 슬롯) 해시라 재추출 시 모델이 맨 위 행을 하나 더/덜 읽으면 이후 id 가 밀린다. F03 안에서는 자산 단위 교체라 무해하지만, F04 가 id 로 사용자 수정을 보관한다면 **성공 자산은 재추출하지 않는다** 는 규칙(merge_retry 가 강제)이 전제다.

## 실제 캡처로 고친 것 (p1 → p3, f03-0.1 → 0.4)

- 행에 날짜가 없는 화면(일별 보기)용 `header_date` 추가, 빈 날짜 허용. 전에는 4장 중 3장이 스키마 교정 재시도를 타서 장당 13초.
- 표시 월 비교를 문자열 일치에서 숫자 추출로 변경 ("8월" vs "2026-08" 오탐 제거).
- 사람 이름은 `개인`으로 치환 (명세 "계좌번호·이름 미추출"). 금액 0인 잘린 조각 행 제거.
- 날짜를 못 읽은 행은 자리표시자 없이 `""` + `date_missing`. F04 검토 큐에서 사용자 입력.

## 세트 확대 (수용 기준 주장 전 필수)

- 정답 기입 방식 변경: 템플릿 없이 캡처를 보고 직접 기입하거나 2인 교차 검수
- 카드사 앱 (삼성·현대·신한): 할부·취소 표기, 긴 가맹점명
- 거래 화면이 아닌 이미지 → `skipped` / `no_transactions` 확인
- 한 장에 20행 이상 (max_tokens 여유 확인), 두 줄 행 병합
- 명세가 지목한 오독 지점: 0/8, 1/7, 쉼표 자릿수, 색상만으로 구분되는 입출금
- 1월 슬롯의 12월 거래 (연도 경계)
- 목표 150행 이상. `cache_read_input_tokens` 도 함께 기록
