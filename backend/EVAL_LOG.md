## 배포·운영 메모 (2026-11-15)

팀 EC2 에 백엔드(BE main, `ownerName`·`filePassword` 포함)·`ai`·mysql 세 컨테이너가 올라갔다. `.github/workflows/ai-image.yml` 도 처음으로 끝까지 성공했다 (이미지 빌드 → Docker Hub → EC2 `docker compose pull ai && up -d ai`, 중간 명령 실패는 `script_stop` 으로 워크플로 실패로 표시). 운영 컨테이너에서 실제 업로드로 API 키 동작을 확인하는 것은 아직 남아 있다.

**owner_name 은 선택값이다.** 백엔드는 온보딩에서 `ownerName` 을 받았을 때만 `/extract`·`/extract/retry`·`/parse` 에 `owner_name` 을 넘기고, 없으면 빈 값이 간다. 빈 값일 때 `.env` 의 `F03_OWNER_NAME` 으로 대체하지 않는다 (그 값은 로컬 평가 전용이고 운영 `.env` 에는 없다). 이름이 없어도 사람 이름을 "개인" 으로 적는 규칙, "내 계좌 이체" 행을 self_transfer 로 올리는 `infer_self_transfer`, 파일 파서의 "본인" 토큰 승격은 그대로 동작한다. 달라지는 것은 하나다: 주인 이름이 상대방 자리에 보이는 행(내 다른 은행 계좌로 보낸 송금 등)이 "본인"·self_transfer 대신 "개인"·transfer 로 적혀, 백엔드 규칙상 지출로 집계된다. 월 합계가 그만큼 커질 수 있으니 프론트 온보딩에서 이름을 받는 쪽이 낫다.

**`_05` 일별 헤더 날짜 변동은 그대로 남겨 둔다.** 날짜 구분 헤더("26일") 아래 4행의 날짜를 4회 중 1회 비우는 변동으로, 비운 행은 `date_missing` 으로 S03 검토 큐에 올라가고 금액·방향은 맞다. 고치려면 프롬프트 규칙을 바꾸고 29장을 다시 돌려야 해서 데모 뒤로 미룬다.

**백엔드에 S01 업로드 경로가 하나 더 생겼다** (`POST /api/transactions/upload`, 백엔드가 직접 엑셀을 읽음). 토스 내보내기 파일은 머리글이 첫 행이 아니라 이 경로로는 읽히지 않고, `/parse`·`/classify` 와 기간 정보를 건너뛴다. 팀에 `POST /api/sessions` 하나로 통일하자고 제안했고 프론트는 동의했다.
